Contexto
O que essa automação resolve
Hoje a conciliação bancária é feita manualmente toda semana — exportando dados, cruzando planilhas, conferindo saldos, formatando e-mail. O objetivo é automatizar esse processo de ponta a ponta, mantendo Kamilla no controle da validação final antes de enviar para a contabilidade.
💡

Governança clara: O workflow não executa nada automaticamente. Kamilla clica para rodar, confere o resultado no Sheets, valida o checklist de fechamento e decide se envia o e-mail. Nenhuma ação sem aprovação humana.

🏦

Hoje (manual)

Exporta planilha do Omie, confere extrato por extrato, preenche Sheets linha a linha, monta e-mail com tabelas.

⚡

Com automação

Clica para rodar, aguarda o workflow buscar dados, cruzar, sinalizar divergências. Kamilla analisa e prepara o e-mail, valida e confirma.

📊

Entregável final

Planilha de conciliação + rascunho de e-mail com indicadores inline para a contabilidade.

Fluxo A — Conciliação Semanal
Como o workflow funciona
Sempre acumulado do dia 01 do mês até o dia conciliado. Disparado manualmente por Kamilla 1x por semana.
📌

Este é o Fluxo A — Conciliação Semanal. Existe também um Fluxo B — Fechamento Mensal, que se conecta a este ao final de cada mês. O Fluxo B aproveita toda a base já conciliada e adiciona análises complementares: conciliação de investimentos, mais contas e aplicações financeiras. O Fluxo B é uma extensão do Fluxo A — não substitui, complementa.

API Omie — Extração da base de pagamentos

O workflow acessa o Omie via API (somente leitura) e busca o relatório "Contas a Pagar e a Receber por mês/ano" filtrando o mês atual + próximo mês. Cria automaticamente as colunas calculadas: Tipo (Pipefy ou Cartão de Crédito), Anexo (OK / Sem Anexo / Não gera doc fiscal / Solicitado) e Responsável (Contas a Pagar ou Diretoria).

API Omie — Saldos das contas

Busca o saldo de todas as 23 contas ativas no Omie (contas correntes, cartões de crédito, Caixinha, SWILE, Onfly, XP). Saldo do dia conciliado para cada conta, com dados de instituição, agência e número.

23 contas Bradesco · Santander · Itaú · Safra · XP · Citibank

Google Drive — Coleta de extratos e faturas

Acessa a pasta do mês correspondente no Drive (Conciliação Bancária / 2026 / 08. Agosto) e localiza os arquivos pelo padrão de nomenclatura. Arquivos com "Fatura" no nome → cartão de crédito. Demais → conta corrente. Prioriza Excel para leitura; PDF fica como evidência. Kamilla faz o upload manualmente antes de rodar.

Google Drive Upload manual por Kamilla PDF + Excel
4

Google Sheets SWILE — Planilha do DP

Lê a aba "SWILE Financeiro 2026" da planilha do DP, localiza o bloco semanal correspondente ao período e extrai: saldo final, TEDs recebidas por CC, total por categoria. Cruza com os lançamentos da conta SWILE no Omie.

Google Sheets API Atualizada semanalmente pelo DP
5

Qive — Conciliação fiscal NF vs Omie

Busca as NF-e e NFS-e emitidas contra o CNPJ da Logcomex no período. Cruza com os lançamentos do Omie por CNPJ + número da NF. Identifica: notas conciliadas OK, divergências de valor/razão social/tipo de documento, notas na Qive não lançadas no Omie, notas canceladas.

Bloco separado NF-e + NFS-e Aba própria no Sheets

* É a partir deste bloco que começaria a conexão com o fluxo da Carol, caso optemos pelo Cenário 2 — aproveitando a extração do Omie que ela já tem configurada.

6

AI Agent — Análise crítica e cruzamento

Aplica as 15 regras de validação (R1 a R15) na base de pagamentos. Confere entradas, saídas e saldo diário de cada conta corrente vs. extrato do banco. Valida SWILE contra planilha do DP. Gera Top 10 por fornecedor, categoria, CC e departamento. Compara com histórico acumulado na memória (threshold: 50% + R$20.000 de variação).

R1 a R15 Top 10 fornecedores Variação mensal Memória acumulada
7

Google Sheets — Planilha de conciliação (8 abas)

O workflow cria/atualiza a planilha com todas as abas: Saldo das Contas (verde/vermelho por conta), Base de Pagamentos, Conciliação Qive, Indicador de Anexo (4 blocos com meta de 80% OK), Análise Crítica, Análises Quantitativas, Resumo Executivo e Checklist de Fechamento. Kamilla revisa e trata cada ponto antes de liberar o e-mail.

8 abas Meta 80% anexos OK Checklist de validação

Gmail — Rascunho do e-mail de fechamento

RECOMENDADO
Cenário 1
Fluxo independente
Kamilla tem seu próprio workflow completo no ailab.logcomex.com, com credenciais próprias da API Omie. Totalmente independente do fluxo da Carol.
Diagrama do fluxo
🖱️ Gatilho Manual (Kamilla)
↓ 🔌 API Omie (credencial própria)
↓ 📁 Drive → Extratos
↓ 📄 SWILE Sheets
↓ 🔍 Qive
↓ 🤖 AI Agent → Análise R1–R15
↓ 📊 Google Sheets (8 abas)
↓ ✉️ Rascunho Gmail
✓ Vantagens
  • Auditável — fluxo 100% rastreável e de propriedade da Kamilla
  • Independente — nenhuma dependência de terceiros
  • Seguro para o curso (entrega do JSON próprio)
  • Sem risco de quebrar se o fluxo da Carol mudar
× Desvantagens
  • Precisa de credencial própria das APIs — Omie e Qive
  • A Carol já tem ambas configuradas — será necessário avaliar o compartilhamento
Cenário 2
Conectado ao fluxo da Carol
O fluxo da Carol resolve a extração do Omie. Kamilla "herda" essa perna via webhook e adiciona seus blocos de análise depois.
Diagrama do fluxo
🔌 API Omie (fluxo da Carol)
↓ Webhook → passa dados para Kamilla
🖱️ Gatilho Kamilla recebe os dados
↓ 📁 Drive → Extratos
↓ 📄 SWILE Sheets + 🔍 Qive
↓ 🤖 AI Agent → Análise R1–R15
↓ 📊 Google Sheets + ✉️ Gmail
✓ Vantagens
  • Resolve o problema da API Omie sem credencial própria
  • Uma só chamada à API — menos sobrecarga
× Desvantagens
  • Depende do fluxo da Carol — se ela mudar, quebra
  • Dados diferentes podem não bater (Carol extrai o mesmo que Kamilla precisa?)
  • Dificulta auditoria — responsabilidade dividida
  • Preciso rodar a automação de forma independente e minhas conferências são diferentes das que ela entrega
