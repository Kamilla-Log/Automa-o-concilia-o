Contexto
O que essa automação resolve
Hoje a conciliação bancária é feita manualmente toda semana — exportando dados, cruzando planilhas, conferindo saldos, formatando e-mail. Com a automação, tudo é criado automaticamente, liberando Kamilla para análises mais profundas e entregando o fechamento com mais agilidade — antes do prazo normal, com mais tempo para fechar com qualidade.
💡

Governança clara: O workflow não executa nada automaticamente. Kamilla clica para rodar, confere o resultado no Sheets, valida o checklist de fechamento e decide se envia o e-mail. Nenhuma ação sem aprovação humana.

🏦

Hoje (manual)

Exporta planilha do Omie, confere extrato por extrato, preenche Sheets linha a linha, monta e-mail com tabelas.

⚡

Com automação

Tudo é criado automaticamente. Kamilla foca em análises mais profundas, entrega o fechamento com mais agilidade e antes do prazo normal — com mais tempo e qualidade.

📊

Entregável final

Planilha de conciliação + rascunho de e-mail com indicadores inline para a contabilidade.

Sempre acumulado do dia 01 do mês até o dia conciliado. Disparado manualmente por Kamilla 1x por semana.

GitHub Actions — Gatilho semanal

Disparo gratuito, sem teto de crédito. Kamilla clica para rodar manualmente uma vez por semana. Não há execução automática — ela sempre valida o rascunho antes de enviar.

Gatilho manual Sem custo adicional
2

HTTP Request — API Omie (somente leitura)

Busca dois relatórios do Omie: (a) "Contas a Pagar e a Receber por mês/ano" filtrando o mês atual + próximo mês — 30 colunas + 3 calculadas automaticamente (Tipo, Anexo, Responsável); (b) saldo de todas as 23 contas ativas (contas correntes, cartões, Caixinha, SWILE, Onfly, XP).

30 colunas + 3 calculadas 23 contas Somente leitura
3

Drive + Sheets SWILE — Coleta de arquivos (node único parametrizado)

Acessa a pasta do mês no Drive (Conciliação Bancária / 2026 / 08. Agosto) e localiza os arquivos pelo padrão de nomenclatura — "Fatura" no nome → cartão; demais → conta corrente. Prioriza Excel; PDF fica como evidência. No mesmo node, lê a planilha SWILE do DP e extrai: saldo final, TEDs recebidas por CC e total por categoria. Kamilla faz o upload antes de rodar.

Node único parametrizado Upload manual por Kamilla PDF + Excel + Sheets DP
4

HTTP Request — Qive (conciliação fiscal NF vs Omie)

Busca as NF-e e NFS-e emitidas contra o CNPJ da Logcomex no período. Cruza com os lançamentos do Omie por CNPJ + número da NF. Identifica: notas conciliadas OK, divergências de valor/razão social/tipo de documento, notas na Qive não lançadas no Omie, notas canceladas.

Conciliação fiscal NF-e + NFS-e Aba própria no Sheets
5

Code Python — Validação R1 a R15 (sem IA no meio)

Aplica as 15 regras de validação determinísticas na base de pagamentos. Confere entradas, saídas e saldo diário de cada conta corrente vs. extrato do banco. Valida SWILE contra planilha do DP. Gera Top 10 por fornecedor, categoria, CC e departamento. Compara com histórico acumulado no Supabase (threshold: 50% + R$20.000 de variação). A IA só entra depois — nenhuma inferência aqui.

R1 a R15 Top 10 fornecedores Variação mensal Sem IA no meio
6

Supabase — Armazenamento e auditoria

Persiste os dados da conciliação para histórico e auditoria. Alimenta a memória do AI Agent com o histórico acumulado dos meses anteriores — viabilizando a análise de variação percentual e valores absolutos por fornecedor, categoria e departamento.

Base de dados Histórico acumulado Auditoria
7

AI Agent — Resumo executivo + insights (só no final)

Com toda a base já validada pelo Python, o AI Agent gera o resumo executivo da conciliação: principais divergências, variações relevantes em relação ao histórico, alertas e insights do período. Só entra no final do fluxo — as regras determinísticas R1–R15 rodam 100% em código.

Resumo executivo Insights do período Só no final
8

Google Sheets — Planilha de conciliação (8 abas)

O workflow cria/atualiza a planilha com todas as abas: Saldo das Contas (verde/vermelho por conta), Base de Pagamentos, Conciliação Qive, Indicador de Anexo (4 blocos, meta 80% OK), Análise Crítica R1–R15, Análises Quantitativas, Resumo Executivo e Checklist de Fechamento. Kamilla revisa e trata cada ponto antes de liberar o e-mail.

8 abas Meta 80% anexos OK Checklist de validação
9

Gmail — Rascunho do e-mail semanal

Cria rascunho no Gmail de Kamilla com: período conciliado, tabelas de indicador de anexo (Cartão e Pipefy) inline no corpo, insights gerados pelo AI Agent, link do Sheets e link do Drive. Kamilla revisa e decide se envia. Destinatários: Maiara, Thaynara, Niccolas, Thaiane, Adriano, Matheus, Caroline.

Decisão: Fluxo separado no N8N interno da Carol

Dados financeiros sensíveis não vão para ambiente de terceiros (ailab.logcomex.com do curso). O fluxo será construído no N8N interno administrado pela Carol, onde a Duda já desenvolve o projeto de contas a receber. Os dois fluxos (Kamilla e Carol) operam em momentos e com finalidades diferentes — não faz sentido conectá-los.

RECOMENDADO
Cenário 1
Fluxo independente
Kamilla tem seu próprio workflow completo no ailab.logcomex.com, com credenciais próprias da API Omie. Totalmente independente do fluxo da Carol.
Diagrama do fluxo
🖱️ Gatilho Manual (Kamilla)
↓ 🔌 API Omie (credencial própria)
↓ 📁 Drive → Extratos
↓ 📄 SWILE Sheets
↓ 🔍 Qive
↓ 🤖 AI Agent → Análise R1–R15
↓ 📊 Google Sheets (8 abas)
↓ ✉️ Rascunho Gmail
✓ Vantagens
  • Auditável — fluxo 100% rastreável e de propriedade da Kamilla
  • Independente — nenhuma dependência de terceiros
  • Seguro para o curso (entrega do JSON próprio)
  • Sem risco de quebrar se o fluxo da Carol mudar
× Desvantagens
  • Precisa de credencial própria das APIs — Omie e Qive
  • A Carol já tem ambas configuradas — será necessário avaliar o compartilhamento
Cenário 2
Conectado ao fluxo da Carol
O fluxo da Carol resolve a extração do Omie. Kamilla "herda" essa perna via webhook e adiciona seus blocos de análise depois.
Diagrama do fluxo
🔌 API Omie (fluxo da Carol)
↓ Webhook → passa dados para Kamilla
🖱️ Gatilho Kamilla recebe os dados
↓ 📁 Drive → Extratos
↓ 📄 SWILE Sheets + 🔍 Qive
↓ 🤖 AI Agent → Análise R1–R15
↓ 📊 Google Sheets + ✉️ Gmail
✓ Vantagens
  • Resolve o problema da API Omie sem credencial própria
  • Uma só chamada à API — menos sobrecarga
× Desvantagens
  • Depende do fluxo da Carol — se ela mudar, quebra
  • Dados diferentes podem não bater (Carol extrai o mesmo que Kamilla precisa?)
  • Dificulta auditoria — responsabilidade dividida
  • Preciso rodar a automação de forma independente e minhas conferências são diferentes das que ela entrega
